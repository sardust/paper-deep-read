# 论文深度精读（三层分析法）

## 核心原则

**不要顺着论文目录读，要逆着作者动机拆。**

作者写论文的顺序是「我做了什么」，读者需要重建的顺序是「为什么非做不可」。每写一句话，先自问：

> 这句话是在解释上一步的「为什么不够」吗？
> 如果不是，这句就是废话。

这条纪律贯穿整个流程，它是判断一句话该留还是该删的唯一标准。

## 选择深度

- **快扫（约 3 分钟）**：只做第 1 步 + 第 8 步。用于判断一篇论文是否值得深读、是否与自己的方向相关。
- **标准拆解（20-40 分钟）**：完整走完 1→7 步。用于组会汇报、文献综述、写论文时的相关工作引用。
- **迁移分析**：额外走第 9 步。用于判断「这篇能不能用到我的任务上」。

用户未指定时，默认走标准拆解。

## 执行流程

### 0. 获取全文

若输入是 PDF 路径，先抽取文本：

```bash
python scripts/pdf_extract.py <pdf路径> --out <输出md路径>
```

脚本按页输出 Markdown，保留页码标记（`<!-- page N -->`），便于把每条证据锚定到具体页码/表号。若脚本不可用（例如 PDF 是扫描件），改用 Read 工具直接读取 PDF，或向用户索要文字版。

抽取后先做一次通读定位：标题、摘要、引言末尾的贡献列表、方法章节标题、实验设置、表格清单、参考文献规模。**这一步只定位不分析。**

### 1. 一句话定位

按三个公式各写一句话，每句不超过 30 字：

- **领域** = 场景 + 任务域（例：太阳活动监测 × 日冕物质抛射检测）
- **具体问题** = 现有方法的缺口 + 作者要补的那一刀
- **主线** = 为了解决（问题缺口），作者通过（核心手段），将系统从（原能力）推进到（新能力）

主线写成一条箭头链：现有缺口 → 作者手段 → 能力跃迁。

若这一步写不出来，说明还没读懂这篇论文，继续读，不要往下走。

### 2. 主矛盾与次要矛盾

- **主矛盾** = 作者最想解决、决定整篇论文成立与否的那个冲突。通常问法：为什么现有路线「根本不够」。
- **次要矛盾** = 为了把主矛盾落进实现，方法设计里必须继续处理的冲突。通常问法：即使往前走，还会卡在哪。

一个主矛盾配 1-3 个次矛盾。次矛盾往往正是那些看起来「多余」的模块的真正来源——找不到次矛盾，说明还没看清模块为什么存在。

### 3. 问题层

只回答一件事：**作者认为最深的问题是什么，不是什么。**

> 作者认为最深的问题是 ___，而不是 ___。

「而不是」那半句必须写。写出反面对照，才证明真的抓住了作者的判断。

### 4. 机制层

只回答一件事：**每个模块各自解决哪个矛盾，不解决什么。**

逐个模块填：

> 为了解决 ___（主矛盾），作者用 ___（模块名），它解决的是 ___，但不解决 ___。

关键在「但不解决」——它就是下一个模块存在的理由，也是思维链的下一环。若某个模块填不出「不解决什么」，说明它是装饰，直接在证据层用消融结果验证或证伪。

### 5. 思维链

把机制层串成一条链，每一步都必须包含「还不够」的转折：

> 核心矛盾 → 第一层解法 → 剩余缺口 → 第二层解法 → 新风险/新代价 → 第三层解法 → 证据验证

写成流水句：`问题 → 补法1 → 还不够 → 补法2 → 又出问题 → 补法3 → 实验证明`。

### 6. 证据层

只回答一件事：**哪张表、哪个消融、哪个案例，真正支撑了作者哪一句主张。**

先反向设问：**作者最想证明哪三句话？** 通常是这三条（可按论文实际情况改写）：

1. 这套方法整体有效，不只是能讲故事。
2. 不仅有效，而且在某个关键维度上更优（效率 / 复杂推理 / 泛化 / 可信性 / 精度）。
3. 某个关键模块不是装饰，而是必要的。

然后**每条主张只找一条最强证据**，按此格式写，并强制补「边界」：

> 【主张1】作者想证明：___
> 【证据】Table/Figure/Ablation ___ 【这条证据说明】___
> 【边界】它证明的是 ___，不是 ___

**证据强度分级**（同层级内优先选强的）：

| 级别 | 证据类型 | 说明 |
|---|---|---|
| A | 主结果表 + 明确 SOTA 数字 + 同等算力/数据设置 | 唯一能支撑「更优」的硬证据 |
| B | 消融实验（逐模块/逐项） | 唯一能支撑「模块必要」的硬证据 |
| C | 参数敏感性 / 复杂度分析 | 支撑「稳定」「代价可控」 |
| D | 可视化案例 / 定性图 | 只能做辅助叙述，不可单独支撑主张 |
| E | 作者自述、无实验支撑的声明 | 明确标记为「未验证」 |

**边界纪律（最容易翻车的地方）**：C、D 级证据不得单独支撑主张 2。凡是作者没做但读者会默认的事（未做的公平性对比、未报告的运行开销、未验证的跨域泛化），一律显式列入第 7 步的三重边界，而不是替作者打圆场。

### 7. 三重边界

每篇论文都要写满三条，这是防止「读完就过度信任」的关键环节：

> 【边界1：能力边界】该方法可以做到 ___，但不能做到 ___，因为 ___
> 【边界2：系统边界】该方法解决的是 ___，但没有覆盖 ___，因此还不能直接用于 ___
> 【边界3：场景/假设边界】该方法依赖 ___，在 ___ 情况下可能失效或不稳定

三条边界都必须从论文自身证据倒推得出（有具体的「因为…」），不能写成放之四海皆准的套话。若某个实验设置明显限制了结论（如仅在单一数据集、单一分辨率、特定信噪比下验证），必须落到边界里。

### 8. 创新点

**不要写成模块罗列。** 用公式：

> 创新点 = 旧方法卡在哪 + 作者具体补哪一刀 + 解决到什么程度

> 现有方法在 ___（具体问题）上存在 ___（明确缺口），作者通过 ___（具体机制），解决了 ___（具体能力），但仍未解决 ___

每条创新点都要落在第 7 步的某条边界上——**说不出边界的创新点不是创新点，是包装。**

### 9. 迁移到用户自己的任务

仅当用户关心「能不能借鉴」时执行。

先确认其任务约束（上下文中已有则直接使用），再填：

> 【任务定位】这篇论文推进的是 ___（任务链中的哪一段）
> 【可复用能力】我可以直接借用 ___，因为它解决了 ___ 问题
> 【不可复用部分】我不能直接使用 ___，因为它没有解决 ___
> 【缺口（必须补）】如果用于我的任务，我还需要补 ___
> 【我的切入点】因此我的工作可以从 ___ 入手，在 ___ 约束下，实现 ___

若用户的任务有明确部署约束（如端侧、实时、算力上限），必须显式做这个推导：

> 【核心矛盾】如果始终采用重推理路径，虽然 ___，但会导致 ___。如果统一采用轻量路径，虽然 ___，但会导致 ___。因此真正的问题不是单纯「模型太大」，而是 ___。
> 【研究切口】切入点不是直接做压缩本身，而是研究如何根据 ___ 动态分配计算，并结合 ___ 实现轻量化，最终在 ___ 前提下达到 ___。

## 输出格式

默认**直接在对话回复中输出 Markdown**，不默认生成文件。用户要求存档、导出为 Word，或要用于组会/汇报时，改走第 10 步的报告模式。

对话回复结构固定为：

```markdown
## 一句话定位
## 主矛盾 / 次要矛盾
## 问题层
## 机制层（含思维链）
## 证据层（三条主张 × 最强证据 × 边界）
## 三重边界
## 创新点
## 迁移到我的任务（可选）
## 一句话结论
```

最后一节必须给出可执行判断，而非复述：值不值得跟 / 跟哪一条线 / 什么条件下这篇的结论不成立。

## 常见失败模式（自查）

- **把作者 claim 当事实**：作者说「显著提升」→ 必须落到具体数字和表格。
- **抄摘要**：摘要的措辞是作者的自我呈现，本 skill 要的是拆解后的逻辑结构。
- **创新点写成模块清单**：「提出了 A 模块和 B 模块」不是创新点，「补上了 X 场景下 Y 能力缺失」才是。
- **机制层缺「不解决什么」**：这是链条断裂的信号，回到第 4 步重填。
- **边界写成套话**：「可能需要更多数据验证」这种句子应删除，换成从论文具体实验设置倒推出的边界。
- **证据张冠李戴**：每条主张单独核对其对应的表号，不要把消融结果当主表结果引用。

## 批量拆解（一次多篇）

用于文献综述横向对比时，对每篇独立走完 1→7 步，然后输出一张对比表，维度固定为：
领域 / 主矛盾 / 核心手段 / 能力跃迁 / 最强证据（表号）/ 最大边界 / 可复用点。

不要因为篇数多就跳过边界一列——横向对比的价值恰恰在边界差异上。

## 10. Word 精读报告模式

用户要求「做成报告/导出 Word/组会材料」时执行。先在对话里把 1→7 步拆完（结论要一致），再生成文档。

**工作目录**：建一个临时工作目录（例如 `<cwd>/paper-report/<论文短名>/`），所有中间产物放这里。

**Step 10.1 抽取论文原图**

```bash
python scripts/pdf_figures.py <pdf> --out-dir <工作目录>/figs
```

脚本扫描矢量绘图与位图，聚类成图区后按页导出 PNG，并生成 `manifest.json`（含页码、裁剪框、像素尺寸）。

**Step 10.2 用 Read 工具逐张确认**

导出后**必须**用 Read 工具查看每张图，判断它是「方法示意图」「实验结果图」「定性案例图」还是「无关装饰」。确定每张图对应论文里的哪个图号与页码，并判断它能支撑哪条主张。

**这一步不能省。** 不看图就写图注，必然张冠李戴。

**Step 10.3 生成自制图示**

用 `scripts/make_figures.py` 生成两张必备图示。含中文时**必须用 `--json` 传参**（Bash 传中文会被拆成多个参数导致崩溃）：

```bash
# 思维导图：中心主矛盾 + 右侧因果修补链（items[0] 是根节点）
python scripts/make_figures.py --kind mindmap --json <mm.json> --out <工作目录>/figs/mindmap.png

# 结构图：纵向阶段流程，呈现三层拆解
python scripts/make_figures.py --kind structure --json <st.json> --out <工作目录>/figs/structure.png
```

JSON 格式：`{"title": "...", "items": [["标签","说明"], ...]}`

**Step 10.4 组装 report.json 并生成 Word**

按下方 schema 写 `report.json`，然后：

```bash
python scripts/build_report_docx.py <report.json> --out <输出.docx>
```

### report.json schema

```json
{
  "meta": {"title":"","subtitle":"","authors":"","venue":"","date":"","pdf":"","tags":[]},
  "sections": [
    {"heading":"", "level":1, "blocks":[ ... ]}
  ]
}
```

block 类型：

| type | 字段 | 用途 |
|---|---|---|
| `para` | `text` | 段落，支持 `**加粗**` |
| `bullets` / `numbered` | `items[]` | 列表 |
| `table` | `header[]`, `rows[][]`, `widths[]` | 表格 |
| `kv` | `items[[k,v]]`, `key_header`, `val_header` | 两列对照表（机制层常用） |
| `image` | `path`, `caption`, `source`, `highlight`, `width_cm` | **插图**，`source` 必填 |
| `callout` | `tone`(info/warn/ok/danger/gray), `title`, `text` | 强调框 |
| `evidence` | `claim`, `evidence`, `boundary`, `level`(A-E) | 证据三件套，自动渲染强度标签 |
| `boundary` | `kind`, `text` | 三重边界条目 |
| `quote` | `text`, `source` | 论文原文引用 |
| `pagebreak` | — | 分页 |

### 报告的图表纪律

**这是本模式的核心要求，不可省略：**

1. **论文原图必须引用而非搬运**：`source` 字段必须写明「论文 Figure X（第 N 页）」。没有来源标注的插图视为学术不规范。
2. **原图必须配「核心结论」**：`highlight` 字段写清这张图到底支撑了哪条主张。禁止只贴图不解读。
3. **自制图示用于呈现逻辑结构**：思维导图（主矛盾→修补链）和结构图（三层拆解）由本skill 生成，用于替代论文原文的目录式罗列。
4. **张冠李戴是本模式的头号翻车点**：每张原图的图号、页码、所支撑的主张，都必须在 Step 10.2 看图时确认。禁止凭抽取顺序猜测图号。
5. **证据强度标签必须体现在文档里**：用 `evidence` block，让读者一眼看出哪些主张有硬证据、哪些只是作者自述。

### 报告章节建议顺序

```markdown
# 标题页（标题/作者/期刊/原文文件名）
## 核心摘要（一页读懂：主线 + 结论 + 是否值得跟）
## 一、问题层：作者认为的最深问题
## 二、机制层：思维链与模块拆解   ← 插入自制思维导图
## 三、证据层：三条主张与最强证据  ← 插入论文实验图（带 highlight）
## 四、三重边界
## 五、创新点
## 六、迁移到我的任务（可选）
## 七、一句话结论
```

完成后必须调用 `present_files` 展示 Word 文档，并**在回复里说明每张图对应论文的哪个图号、支撑哪条主张**。
