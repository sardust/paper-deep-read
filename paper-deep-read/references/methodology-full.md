# 方法论原始条款与完整模板

本文件保留方法论的原始表述，供需要精确措辞时使用。正文流程见 `SKILL.md`。

---

## 一、基础公式

```
领域= 场景 + 任务域
具体问题 = 现有方法的缺口 + 作者要补的那一刀
主线 = 为了解决（问题缺口），作者通过（核心手段），将系统从（原能力）推进到（新能力）
主线 = 现有缺口 → 作者手段 → 能力跃迁

主矛盾 = 作者最想解决、决定整篇论文成立与否的那个冲突
次要矛盾 = 为了落地主矛盾，方法设计里必须继续处理的实现冲突

主矛盾 = 为什么现有路线根本不够
次要矛盾 = 即使往前走，也还会卡在哪

思维链 = 核心矛盾 → 第一层解法 → 剩余缺口 → 第二层解法 → 新风险/新代价
        → 第三层解法 → 证据验证
问题 → 补法1 → 还不够 → 补法2 → 又出问题 → 补法3 → 实验证明

创新点 = 旧方法卡在哪 + 作者具体补哪一刀 + 解决到什么程度
```

## 二、三条填空模板（逐句填空版）

### ① 论文主线链（回答：为什么要做这件事）

```
因为现有 ___（领域现状），无法 ___（核心能力缺口），
所以作者先 ___（定义问题/构建任务/提出框架），
但这只能解决 ___（它的作用边界），不能解决 ___，
因此作者进一步 ___（提出核心方法/系统），
目标是把系统从 ___ 推进到 ___。
```

### ② 方法设计链（回答：为什么模块必须这样一步步出现）

```
因为 ___（实现层矛盾1），
所以作者先 ___（设计1），
但这只能解决 ___，仍然无法 ___，
因此作者又 ___（设计2），
可这样会带来 ___（新问题/副作用），
于是作者再 ___（设计3），
最终形成 ___（一句话总结方法链：A→B→C）。
```

### ③ 证据闭环链（回答：作者怎么证明不是拍脑袋）

```
为了验证 ___（核心主张1），作者通过 ___（实验类型1）说明 ___；
为了验证 ___（核心主张2），作者通过 ___（实验类型2）说明 ___；
为了验证 ___（模块必要性），作者通过 ___（消融实验）说明 ___；
进一步通过 ___（泛化/案例/分析），说明 ___。
```

## 三、逐句自检纪律

> 你每写一句话，都问自己一句：
> 👉「这句话是在解释上一步的『为什么不够』吗？」
> 如果不是，这句就是废话。

## 四、三层拆解法

把论文拆成「三层」，每层只回答一个问题。**不要顺着论文目录读，要逆着作者动机拆。**

- **第一层 问题层**。只回答：作者认为最深的问题是什么，不是什么。
- **第二层 机制层**。只回答：每个模块各自解决哪个矛盾，不解决什么。
- **第三层 证据层**。只回答：哪张表、哪个消融、哪个案例，真正支撑了作者哪一句主张。

填空版：

```
【问题层】
作者认为最深的问题是 ___，而不是 ___

【机制层】
为了解决这个问题，作者用 ___，它解决的是 ___，但不解决 ___

【证据层】
作者通过 ___（具体实验/表/消融），支撑「___（一句主张）」
```

## 五、三条主张与最强证据

作者最想证明的是：你要反过来问「作者最想证明哪三句话？」然后每句话只找一条最强证据。

```
主张1：作者想证明这套方法整体是有效的，不只是能讲故事。
主张2：作者想证明这套方法不仅有效，而且在某个关键维度上更优
      （比如复杂推理、效率、泛化、可信性）。
主张3：作者想证明某个关键模块不是装饰，而是必要的。
```

自行套用时的三个常见组合：**整体有效 / 兼顾效率 / 模块必要**。

填空版：

```
【主张1】作者想证明：___
【证据】Table / Figure / Ablation ___ 【这条证据说明】___
【边界】它证明的是 ___，不是 ___
```

## 六、三重边界

```
【边界1：能力边界】该方法可以做到 ___，但不能做到 ___，因为 ___
【边界2：系统边界】该方法解决的是 ___，但没有覆盖 ___，因此还不能直接用于 ___
【边界3：场景/假设边界】该方法依赖 ___，在 ___ 情况下可能失效或不稳定
```

## 七、创新点填空版

```
【创新点1】
现有方法在 ___（具体问题）上存在 ___（明确缺口），
作者通过 ___（具体机制/设计），解决了 ___（具体能力），
但仍未解决 ___（边界）
```

## 八、迁移到自己任务的填空版

```
【任务定位】
这篇论文推进的是 ___（任务链中的哪一段）

【可复用能力】
我可以直接借用 ___（方法/机制/思想），因为它解决了 ___ 问题

【不可复用部分】
我不能直接使用 ___，因为它没有解决 ___

【缺口（必须补）】
如果用于我的任务，我还需要补 ___

【我的切入点】
因此我的工作可以从 ___ 入手，在 ___ 约束下（如端侧/实时），实现 ___（具体目标）
```

带部署约束时的加强版：

```
【任务约束】
我的任务是 ___。它要求系统在 ___ 场景中连续完成 ___。
由于部署在 ___，因此受到 ___ 约束。

【核心矛盾】
如果系统始终采用重推理路径，虽然 ___，但会导致 ___。
如果系统统一采用轻量路径，虽然 ___，但会导致 ___。
因此真正的问题不是单纯「模型太大」，而是 ___。

【研究切口】
所以我的切入点不是直接做模型压缩本身，
而是研究如何根据 ___ 动态分配计算，并结合 ___ 实现轻量化，
最终在 ___ 前提下达到 ___。
```
