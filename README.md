# paper-deep-read

[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)

> 按「逆着作者动机拆论文」的三层分析法精读学术论文，输出可追溯的证据链与边界判断，并可一键生成含思维导图、论文原图引用的 Word 精读报告。

一个给 AI Agent 用的**论文精读 Skill**。核心理念一句话：

> **不要顺着论文目录读，要逆着作者动机拆。**

作者写论文的顺序是「我做了什么」，读者需要重建的顺序是「为什么非做不可」。每写一句话先自问：

> 这句话是在解释上一步的「为什么不够」吗？如果不是，这句就是废话。

---

## 它解决什么问题

常见的 AI 读论文有四个通病：

| 通病 | 表现 |
|---|---|
| 抄摘要 | 把作者的自我呈现当分析复述 |
| 证据张冠李戴 | 把消融结果当主表结果引用 |
| 创新点写成模块清单 | 「提出了 A 模块和 B 模块」不等于创新点 |
| 读完就过度信任 | 不写边界，读者无法判断结论何时失效 |

本 skill 用**三重边界 + 证据强度分级**强制暴露这些问题。

## 安装

### 方式一：直接克隆（推荐）

```bash
git clone https://github.com/<你的用户名>/paper-deep-read-skill.git
```

把仓库里的 `paper-deep-read/` 整个目录复制到：

- **Windows**：`C:\Users\<你的用户名>\.workbuddy\skills\paper-deep-read\`
- **macOS / Linux**：`~/.workbuddy/skills/paper-deep-read/`

```bash
# macOS / Linux 一行搞定
git clone https://github.com/<你的用户名>/paper-deep-read-skill.git \
  ~/.workbuddy/skills/paper-deep-read
```

> 注意：仓库根目录下的 `paper-deep-read/` 才是 skill 本体，克隆后需要把它（而不是整个仓库）放进 skills 目录。

### 方式二：让 Agent 代劳

把仓库地址发给 Agent，说「帮我把这个 skill 装上」即可。

### 安装依赖

skill 的核心流程（1→9 步）零依赖，纯文本指令。只有**报告模式**需要 Python 库：

```bash
pip install pymupdf python-docx matplotlib pillow
```

| 脚本 | 依赖 | 用途 |
|---|---|---|
| `pdf_extract.py` | `pymupdf`（或 `pypdf`） | PDF 全文抽取，保留页码锚点 |
| `pdf_figures.py` | `pymupdf` + `pillow` | 从 PDF 裁剪导出实验图 |
| `make_figures.py` | `matplotlib` | 生成思维导图 / 结构图 |
| `build_report_docx.py` | `python-docx` | 生成 Word 报告 |

只做对话内拆解的话，**不需要装任何依赖**。

## 使用

安装后在对话中直接说（不必记命令）：

```
精读这篇论文
```

或点��斜杠命令手动调用：

```
/paper-deep-read
```

### 三种深度

| 你想要 | 就说 |
|---|---|
| 只判断值不值得读（约 3 分钟） | 「**先扫一眼**这篇，看跟我的方向有没有关系」 |
| 完整拆解（组会 / 文献综述用） | 「精读这篇」（默认） |
| 拆解 + 给出你的切入点 | 「精读这篇，**迁移到我的任务**上」 |
| 直接出 Word 报告 | 「精读这篇并**做成 Word 报告**」 |
| 多篇横向对比 | 「**批处理**这三篇，做对比表」 |

### 输出内容

```
一句话定位 → 主矛盾/次矛盾 → 问题层 → 机制层（含思维链）
→ 证据层（三条主张 × 最强证据 × 边界）→ 三重边界 → 创新点
→ 迁移到我的任务（可选）→ 一句话结论
```

## 核心理念

### 三层拆解

| 层 | 只回答一个问题 |
|---|---|
| 问题层 | 作者认为最深的问题是什么，**不是什么** |
| 机制层 | 每个模块解决哪个矛盾，**不解决什么** |
| 证据层 | 哪张表、哪个消融、真正支撑了哪句主张 |

### 证据强度分级

| 级别 | 证据类型 | 说明 |
|---|---|---|
| A | 主结果表 + 明确数字 + 同等设置 | 唯一能支撑「更优」的硬证据 |
| B | 消融实验 | 唯一能支撑「模块必要」的硬证据 |
| C | 敏感性 / 复杂度分析 | 支撑「稳定」「代价可控」 |
| D | 可视化 / 定性图 | 仅辅助叙述，不可单独支撑主张 |
| E | 作者自述、无实验支撑 | 明确标记「未验证」 |

**硬性纪律**：C、D 级证据不得单独支撑「更优」类主张。

### 思维链

```
问题 → 补法1 → 还不够 → 补法2 → 又出问题 → 补法3 → 实验证明
```

「不解决什么」一栏就是下一个模块存在的理由。填不出这一栏，说明该模块是装饰——回��题层重新审视。

### 三重边界

每篇论文都必须写满：

- **能力边界**：能做什么，不能做什么，因为什么
- **系统边界**：解决了什么，没覆盖什么，因此还不能直接用于哪
- **场景/假设边界**：依赖什么，在什么情况下失效

**说不出边界的创新点不是创新点，是包装。**

## Word 报告模式

指定「做成 Word 报告」时启用，含四条图表纪律：

1. **论文原图必须引用而非搬运** —— 必须标注「论文 Figure X（第 N 页）」
2. **每张原图必须配核心结论** —— 说清它支撑哪条主张，禁止只贴图不解读
3. **逐张看图确认图号** —— 不省这步必然张冠李戴
4. **自制图不写来源，原图必写** —— 两者不可混淆

报告含自制思维导图、论文结构图、以及论文实验图引用，示例见 `paper-deep-read/references/report-json-schema.md`。

## 环境说明

- **中文字体**：`make_figures.py` 会自动探测（Microsoft YaHei / SimHei / Noto Sans CJK 等）。Linux 上若无中文字体，图中的中文会显示为方框，需先安装 `fonts-noto-cjk`
- **含中文传参**：`make_figures.py` 必须用 `--json` 传参。Bash 传中文会被拆成多个 argv 导致崩溃
- **PDF 扫描件**：抽取脚本会自动检测并告警，此时应改用支持视觉解析的方式读取 PDF
